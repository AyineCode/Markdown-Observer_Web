# Markdown 阅读器

一个**在浏览器里安静读 markdown** 的小工具：排版、配色、代码块、公式全部沿用 DeepSeek Harness 聊天正文的那一套（样式表是逐条搬过来的，不是照着仿的），外面再套一层为长时间阅读做的壳——可换背景、磨砂玻璃面板、深浅色跟随、目录树、搜索、多文档。

## 两种用法，各给一类人

### A. 一个文件，双击就读（给不懂计算机的朋友）

```
share/
├── markdown-reader.html    ← 双击它，把 .md 拖进去就能读
├── HOW-TO-OPEN.txt           ← 五行说明，不用命令行
└── sample.md            ← 有东西可以马上试
```

把 `share/` 这个文件夹（或其中那个 HTML 文件）发出去就行：不需要装 Node、不需要解压、不需要联网，文件只在对方电脑上打开，不上传任何东西。用 Chrome / Edge 打开还能点「打开文件夹」直接读一整个目录（见下面的说明）。

生成方式：`node tools/build-share.mjs`（会顺带产出单文件 `markdown-reader.html`）。

### B. 文件夹 + 启动器（你自己用：WSL / Linux / macOS / Windows）

```sh
./start.sh ~/notes            # WSL / Linux / macOS：起服务 + 自动开浏览器
./start.sh ~/notes --port 5000
./start.sh --no-open          # 只起服务（服务器上没有桌面时用）
```

Windows：双击 `start.bat`（或把文件夹拖到它上面）。macOS：双击 `start.command`。

启动器会做什么：挑一个空闲端口（从 4321 往上试）→ 起本地服务 → 打开浏览器。**在 WSL 里会自动用 Windows 侧的浏览器打开**（依次尝试 `wslview` → `explorer.exe` → `cmd.exe`，都不行就打印地址让你手动点）。

服务模式比单文件版多了两件事：**根目录由启动参数决定**（可以指向任何文件夹），以及**可分享的深链接**（`?file=文档路径#小节`，复制地址栏就能把某一节发给别人）。

## 功能

### 背景与玻璃：默认最安静，想热闹再热闹

**默认是「无背景」**：没有图也没有彩渐变，只有一层极淡的黑白对角渐变（浅色 `白 → 极浅灰`，深色 `近黑 → 稍亮的黑`），左上角一点几乎看不见的微光。颜色不是写死的，是从当前主题的页面底色里按比例混出来的，所以深浅色自动各得其所。想换：设置面板「背景」页里挑 8 套内置渐变，或选自己的图。

一旦选了渐变或图片，就上三层保险保证“背景不影响阅读”：

1. **模糊**：背景层默认 22px 高斯模糊（可调 0–48），图像细节被打散，只剩氛围；
2. **遮罩**：上面再压一层可调遮罩（默认 30%，深色模式自动加强到约 36%）；
3. **玻璃面板**：正文装在半透明磨砂面板里（`backdrop-filter` + 1px 描边 + 阴影），不透明度默认 **50%**（设置面板里可调 20–95%）。

面板多透，直接决定**按钮看起来多透**：按钮都长在面板上，面板 72% 时按钮后面只剩 28% 的背景色（实测浅色下按钮是 `#e7e9f2`，几乎纯白），调到 50% 后同一颗按钮变成 `#dae2f9`（明显带着背景的蓝紫）。想更透就往 35% 调。

「无背景」下前两层没有作用对象，所以那两行滑杆会被灰掉并在下面说明一句，而不是让你以为滑杆坏了。

浏览器不支持磨砂时自动退回不透明面板——宁可少一点玻璃感，也不能糊。

背景来源：**8 套内置渐变**（含深色系，纯 CSS）、**本地图片**（拖进窗口或从设置里选，自动等比缩到 2400px 转 webp）、**无背景**。

### 按钮：按“重量”分四档，越轻越干净

参考的是 dsh 自己的做法（`ui-sidebar/src/client/SidebarRoot.module.css` 与 `ui-workspace` 的 `.iconButton`：28×28、`border: none`、`border-radius: 50%`、`background: transparent`，只有 hover 才浮出一层 `--dsw-alias-interactive-bg-hover`）。dsh 的取向很清楚：**能用位置和指针暗示的，就不画边框**。于是现在分四档：

| 档 | 谁 | 长什么样 |
|---|---|---|
| **0 · 什么都不画** | 顶栏的搜索 / 设置 / 打印、侧栏的收起与打开文件夹、搜索条上的上一个 / 下一个 / 关闭、侧栏收起后那个“拉出小圆” | 只有图标；hover 时浮出一层很淡的实色（浅色 6% 墨、深色 8% 白）。**故意不用磨砂**：那只是一次“手在上面”的反馈，磨砂既看不出来，还白白多一个 `backdrop-filter`。 |
| **1 · 一块薄玻璃** | 侧栏「打开文件」、「看一篇示例」、「回到原处」、「恢复默认」、空状态三张卡、代码块复制按钮、色板与最近格子 | **不加底色、不描边**（0%）：背景色原样透过来，轮廓全靠**磨砂 + 凸感**。 |
| **2 · 底板 + 小玻璃片** | 主题三态、设置面板的两个页签 | 一整条长玻璃底板 + 只有选中那一格盖一小块玻璃。 |
| **3 · 有色玻璃** | 主操作（`.btn.primary`） | 主题色的半透明底 + 白字。 |

有一条**踩过坑的经验**，写下来省得再犯：**磨砂感来自 `backdrop-filter`，底色只决定“这片玻璃比周围亮还是暗”，而它必须跟着主题换方向**——

| | 静止（第 1 档） | 悬停 | 选中的那一小片（第 2 档） |
|---|---|---|---|
| 浅色主题 | 完全透明：`rgba(38 49 72 / 0)` | 淡墨 `rgba(38 49 72 / 0.06)` | 白 `rgba(255 255 255 / 0.75)` |
| 深色主题 | 完全透明：`rgba(255 255 255 / 0)` | 淡光 `rgba(255 255 255 / 0.06)` | `rgba(255 255 255 / 0.24)` + 更亮的描边 |

**凸感**是这套材质的另一半，由三样东西给出来（`--btn-glass-rim` / `--btn-glass-lift`）：按钮**内顶**一道高光（深色主题下是 `rgba(255,255,255,0.16)`，浅色主题下白高光叠在白面板上等于没有，所以浅色改看**内下缘**那道 `rgba(15,23,42,0.12)` 的暗线）+ 外面一层投影。像素实测：浅色下按钮内下缘比按钮本身暗 **30**、投影比面板暗 **5**；深色下内顶高光比按钮亮 **11**、内下缘暗 **8**。

如果两个主题共用一个“深色低透明”的底色，深色主题下就成了实心黑按钮，浅色主题下按钮又会消失——两种“看着不对”其实是同一个原因。

**切换型按钮**用的是「一整块玻璃底板 + 一小块玻璃片」：底板是那条长玻璃（`--seg-track-alpha`，10%，看得见边界）；**未选中的格子什么都不画**（按钮直接消失，只在悬停时浮出一点点）；**只有选中的那一格盖上一小块玻璃**。

第 1、2 档的模糊是**下限**（默认 10px，`--btn-glass-blur`）。浏览器不支持 `backdrop-filter` 时，这几档退回 dsh 原本那种“实心但干净”的底色，可读性优先；第 0 档本来就是透明的，不受影响。所有数值（含深色主题那几个）都在 `styles/tuning.css`，出厂值在 `styles/reader.css`——**删掉 tuning.css 里的一行就回到出厂值**。

### 深浅色

顶栏三段开关（跟随系统 / 浅色 / 深色），`T` 键循环。机制与 dsh 相同：`<body data-ds-dark-theme>` + `color-scheme`，滚动条、表单控件、原生弹窗都会跟着变；跟随系统时监听 `prefers-color-scheme` 实时响应。

### 阅读

- **目录**：按标题层级生成**可折叠的树**——点三角折叠/展开，点标题文字跳转（两个热区分开，和文件树一样）；默认只展开到二级，滚动时会自动展开当前所在的分支；
- **文内跳转**：标题会生成可读锚点（支持中文，如 `#数学公式`），正文里 `[跳到某节](#锚点)` 点击即跳，目标会闪一下，右上角出现「回到原处」；地址栏同步变化，**可以把某一节的链接直接发给别人**；
- **阅读三件套**：字号（85–140%）、行距（80–150%）、栏宽（560–1000px，默认 748px 正是 dsh 聊天正文宽度）；
- **进度与位置**：顶部 2px 进度条；每篇文档各自记住读到哪；
- **文内搜索**：`/` 或 `Ctrl+F`，命中高亮、当前命中单独标记、上下跳转；
- **代码块**：语言标签 + 一键复制，可切成不换行（横向滚动）——dsh 默认换行，保持一致；
- **图片**：点击开灯箱看大图；
- **打印 / 存 PDF**：`Ctrl+P`，打印样式会去掉背景、玻璃、侧栏与控件，只留黑字白纸，并避免表格/代码块被切页撕开。

### 多文档

侧栏「文档」页里是**打开的文档列表**：当前项高亮、右侧 `×` 关闭（鼠标中键也行），点一下就切过去。每篇文档各自记住滚动位置与搜索状态。

### 侧栏：头部固定，下面一个滚动条装两区

侧栏分三层：**头部**（品牌、根目录、收起按钮）**固定不动**；下面是**文档区**（打开文件 / 打开的文档 / 全部文件树）；再下面是**目录区**（本篇标题）。后两块**共用同一个滚动条**——目录再长也只是往下滚，不会出现"两个区各自滚动、中间那条线抓不住"的问题。

侧栏的开关属于侧栏自己：**展开时**它右上角有一个收起按钮；**收起后**，舞台左上角浮出一个小圆按钮，点它拉回来（`\` 键随时可用）。

### 文件树

服务模式（或单文件版的「打开文件夹」）会给出一棵**可折叠的目录树**：点目录名展开/收起，当前文件高亮，打开文档时会自动展开它所在的目录链——和 Unity 的层级面板是同一个心智模型。

## 快捷键

| 键 | 作用 |
|---|---|
| `/` 或 `Ctrl/Cmd+F` | 文内搜索 |
| `Ctrl/Cmd+O` | 打开文件（可多选，一次开多个） |
| `Alt+1..9` | 切到第 N 个打开的文档 |
| `Alt+[` / `Alt+]` | 上一个 / 下一个文档 |
| `Alt+W` | 关闭当前文档 |
| `T` | 切换深浅色（跟随系统 → 浅 → 深） |
| `\` | 收起 / 展开侧栏 |
| `Enter` / `Shift+Enter` | 搜索里跳到下一处 / 上一处 |
| `Esc` | 关灯箱 → 关搜索 → 关设置 → 收起跳转提示 |
| `Ctrl/Cmd+P` | 打印 / 存 PDF |

> 为什么文档切换用 `Alt` 而不是 `Ctrl+Tab` / `Ctrl+W` / `Ctrl+1..9`：后面这几个都被浏览器占用了（切标签页、关标签页），网页拦不住。`Alt` 组合在网页里是空闲的。

## 设置为什么放在那里

这一版把设置重新摆过，原则是**让控件出现在它所属的地方**，而不是全都塞进一个面板：

| 控件 | 之前 | 现在 | 为什么 |
|---|---|---|---|
| **设置入口** | 顶栏的一个齿轮图标（和搜索/打印混在一起） | **左下角一个带文字的「设置」座位**（固定定位，侧栏收起后依然在） | 它是**全局**设置，不是某一篇文档的设置，不该和文档工具挤在顶栏；放在左下角既显眼，又和 dsh 把设置钉在侧栏底部是同一个取向 |
| 收起 / 展开侧栏 | 在设置面板里 | **侧栏自己头上有收起按钮**；收起后舞台左上角出现小圆拉出按钮；设置里彻底删掉 | 它是界面部件，不是偏好——不该出现在设置里 |
| 打开文件 | 顶栏图标 + 空状态按钮 | **侧栏「文档」页顶部**，顶栏不再重复 | 与 dsh 一致：文件相关操作归侧栏；顶栏只放全局动作 |
| 设置面板 | 一长条，混着外观、排版、背景 | **两页切换**：排版 / 背景（主题只在顶栏，衬线字体归入排版） | 一屏一主题；与顶栏重复的控件不重复放 |
| 侧栏的内容排布 | 用一个分段控件切换「文档 / 目录」 | **上下两区常驻 + 共用一个滚动条** | 两者不是二选一的关系，同时看得见更好；共用一个滚动条之后，目录再长也不用"抢"高度 |
| 每个数值项 | 只有滑杆 | **滑杆 + 可直接输入的数字框** | 拖快、填准；拖到 108% 不用手抖 |
| 最近用过的背景 | 无 | **背景页顶部一行 5 个格子** | 换背景是高频动作，值得一步回退 |

## 持久化：记住什么、不记住什么

设计原则：**阅读器只负责“怎么渲染”，不负责“你读过什么”**。

| 记住 | 存在哪 | 说明 |
|---|---|---|
| 外观、排版、背景的全部设置 | localStorage（键 `md-reader:settings:v4`） | 换台机器就回到默认，符合直觉 |
| 自定义背景图（含最近 5 个背景） | **IndexedDB** | 图很大，localStorage 那 5MB 装不下几张；清理时会自动删掉不再引用的图 |
| 每篇文档读到哪一行 | localStorage | 这是唯一与具体文件相关的记忆；关掉再打开回到原处，不会出现在任何“最近打开”列表里 |
| 侧栏的开合 | localStorage | 视图状态，属于使用习惯 |

| 不记住 | 为什么 |
|---|---|
| 打开过的文件列表 / 最近文件 | 与“只负责渲染”的原则冲突；文件本来就在你自己的目录里 |
| 打开的文档本身 | 每次打开都是新的会话；关掉浏览器不留痕 |

## 与 dsh 的保真度

**逐条搬运，并有机械校验**：`styles/markdown.css` 覆盖了 dsh 两个源样式表的**全部 137 条声明**（`MarkdownText.module.css` + `CodeBlock.module.css`），连注释里写的“为什么”都保留；五张 token 表是整份复制的；语法高亮用 dsh 自己的 `--shiki-*` 调色板。`node tools/check-styles.mjs` 每次校验，缺一条就报错。

保真的细节包括：代码块 `margin: 16px 0` 但非末位时 `margin-bottom: 11px`、`hr` 用 1px 背景而不是 border、引用块只有左边 2px 竖线且没有下边距、表格单元格 `max-width: min(30vw, 320px)`、`h4~h6` 后接列表时收紧到 8px、行内代码 `display: inline-flex` + `font-size: 0.875em`、脚注只做编号不做跳转链接。

**有意的差异**（都是为了“读自己的文档”这个用途）：

| 差异 | dsh 的做法 | 这里的做法 | 为什么 |
|---|---|---|---|
| 原始 HTML | 一律当纯文本转义 | DOMPurify 消毒后渲染 | 你读的是自己的文档，`<details>`、`<img width>` 该能用；脚本与事件属性会被挡掉 |
| 图片 | 只允许绝对 http(s) | 都显示、可点开放大 | 服务模式与文件夹模式会把相对路径接上（前者走 `/api/raw`，后者用浏览器给的句柄） |
| 标题锚点 | 没有 | 自动加可读 id | 目录、文内跳转、深链接都要用 |
| 文件提及按钮 | 有 | 没有 | 那是聊天里的功能，阅读器没有宿主上下文 |
| 公式 | KaTeX 0.16.47 | KaTeX 0.18.7 | 同一族库的更新版本，排版一致 |
| 代码高亮 | shiki（TextMate 语法） | highlight.js + dsh 的调色板 | shiki 要 WASM 与大量语法文件，不适合 `file://` 零构建；配色与代码块外壳一致 |

```
    ├── check-styles.mjs      保真度与 CSS 变量校验
    ├── smoke.mjs             用 jsdom 把整个应用跑一遍
    ├── measure.html          量算页：打印各按钮在浅/深色下的最终颜色
    └── pixels.mjs            真截图量像素：磨砂透不透、切换看不看得出
```

## 自测

三个脚本都不需要浏览器（`cwd` 用 dsh 源码目录，借它的 `jsdom`）：

```sh
cd deepseek-harness-ayine
node ../md-reader/tools/check-styles.mjs                  # 保真度 + CSS 变量（秒级）
node ../md-reader/tools/smoke.mjs                          # 静态模式 + 模拟文件夹模式（114 项断言）
node ../md-reader/tools/smoke.mjs --server                 # 服务模式（113 项断言，含老设置迁移）
node ../md-reader/tools/smoke.mjs --standalone             # 单文件分享版（118 项断言，需先跑 tools/build-standalone.mjs）
DOC_ROOT=../sprite-plugin node ../md-reader/tools/smoke.mjs --server   # 用真实文档目录跑
```

还有两个**真浏览器**工具（不需要看界面，跑完直接出结论）：

```sh
node tools/pixels.mjs                         # 真的截一张图，量像素：磨砂是不是透的、切换看不看得出
READER_URL=http://127.0.0.1:4322 node tools/pixels.mjs   # 想量你正在用的那个服务
```

`tools/pixels.mjs` 会**自己起一个临时服务**（端口 4398，跑完就关，不打扰你正在用的那个），调用 headless Chrome（WSL 里自动用 Windows 侧那个；找不到就跳过），把「按钮底色是否贴着面板 / 深色是不是发亮的雾 / 换背景时按钮像素是否跟着变 / 选中与未选中是否明显不同」四项量出来，任一不达标就非零退出。为什么会需要它：`getComputedStyle` 只能告诉你“声明写对了”，写对了但看着不对（深色主题下一块实心黑按钮就是这么来的）它发现不了。`tools/measure.html` 是配套的量算页，用 `chrome --headless=new --dump-dom` 打开它就能把每个按钮在浅色/深色下的最终颜色打出来。

覆盖：渲染各元素、目录折叠、锚点跳转与深链接、主题、搜索、多文档切换与关闭、侧栏两区共用一个滚动条与收起／拉出、文件树折叠、空状态的三张卡（横排对齐、按环境显隐）、按钮的玻璃配方（磨砂与玻璃变量确实生效）、默认背景与「无背景」的渐变、设置两页与数字框、文件夹模式（用假句柄模拟浏览器的目录选择）、服务模式的目录接口，设置入口不在顶栏、固定在左下角、侧栏为它留了空白，以及 v4 ← 老键的设置迁移（服务模式里逐个开页面，分别塞入老默认值与自选值）。

## 想改外观或默认值，改哪里

只有两个地方，改完保存、刷新页面即生效（改的是页面真正加载的源文件；发给朋友的那份单文件 HTML 要重跑一次 `node tools/build-share.mjs`）：

| 想改的东西 | 文件 | 形态 |
|---|---|---|
| 侧栏宽度、列表行高/圆角/留白、三角大小、两级缩进、正文面板圆角与内边距、顶栏与设置面板圆角、拉出小圆直径、进度条高度、玻璃模糊与饱和度、背景放大倍数、**按钮的玻璃配方**（薄纱浓淡 / 选中态 / 分段底板 / 磨砂半径）、空状态卡片的圆角与图标大小 | `styles/tuning.css` | 一屏 CSS 变量（46 个，含深色主题那一组），每个都带中文注释。**删掉一行就回到出厂默认**——每个用到它的地方都写了同一个数兜底（如 `var(--pull-size, 36px)`） |
| 初始主题、字号、行距、栏宽、代码换行、**默认背景（现在是无背景）**、背景图片模式下的模糊与遮罩、**面板不透明度（现在 50%）** | `js/app.js` 开头的 `DEFAULTS` | 一个 JS 对象，13 个字段，每个都带注释 |

为什么分两处：**尺码属于样式**（浏览器自己会算，不用跑 JS，改完刷新即生效）；**阅读偏好属于用户数据**（要写进 localStorage、要能被设置面板读写、要能一键恢复默认，而且它们由 JS 写成内联样式，优先级天然高于 CSS，放在 tuning.css 里也不会生效）。硬凑成一个文件反而会多出一层“读配置再写进 CSS”的胶水代码。

颜色不在这两处：全部来自 dsh 的那五张 token 表（`styles/base.css` 等），想换配色就改它们。

> 已经用过的浏览器里，`DEFAULTS` 会被 localStorage 里存的那份盖住；点设置面板里的「恢复默认」，或清掉 `md-reader:settings:v4` 即可。
>
> 设置键升级时做过两次迁移，规则都是**只搬“恰好等于老默认值”的那些，自己调过的人原样保留**：
> `v2 → v3` 把老默认背景（极光）改成「无背景」；`v3 → v4` 把老的面板不透明度 72% 改成 50%。迁移规则集中在 `js/app.js` 的 `migrateSettings()` 里，加一条默认值变更就往那里加一行。

## 已知限制

- **视觉效果没有在真实浏览器里验收过**：本机没有可用的无头浏览器，所以布局/动效/磨砂质感的最后一眼需要你自己看。渲染逻辑、DOM 结构与样式一致性由上面的脚本覆盖。
- **「打开文件夹」只支持 Chromium 系**（Chrome / Edge）：这是浏览器的能力（File System Access API），Firefox / Safari 上点它会提示改用服务模式；其余功能不受影响。
- **静态模式（拖入文件）下文档里的相对图片显示不了**：浏览器不允许 `file://` 页面读同目录文件。用服务模式或「打开文件夹」就正常。
- **`file://` 下少数浏览器会禁用本地存储**：设置与阅读位置只在本次会话有效；服务模式下一定可用。
- 不支持 **mermaid** 图（dsh 也不支持）。公式支持 `$...$`、`$$...$$`、`\(...\)`、`\[...\]`。
- 只做阅读，不提供编辑。

## 进阶用法

**启动器参数**

```sh
./start.sh                      # 打开当前目录
./start.sh ~/notes              # 打开指定目录
./start.sh ~/notes --port 5000  # 指定端口
./start.sh --no-open            # 不起浏览器（纯服务）
```

**服务怎么起、怎么停**

```sh
./start.sh ~/notes     # 起服务（已经在跑同一个目录时，它只打开浏览器、不会起第二个）
./stop.sh             # 停掉它
```

启动时会把自己的 PID、端口、文档目录写进 `.md-reader.pid`；`stop.sh` 读它来收工；Ctrl-C 结束也会自动清掉这个文件。所以**不会越起越多**：换个目录再启动，它会先停掉旧的那个。

**服务接口**（服务模式下，插件/脚本也能用）

| 路径 | 作用 |
|---|---|
| `GET /api/info` | 服务信息（模式与根目录） |
| `GET /api/tree` | 根目录下所有 markdown 的路径列表 |
| `GET /api/file?path=…` | 读一个 markdown（返回路径、名称、正文、大小、修改时间） |
| `GET /api/raw?path=…` | 原样读一个文件（文档里的相对图片就走它） |

**深链接**：`http://127.0.0.1:4321/?file=docs%2Fguide.md#安装` 直接打开某篇文档的某一节。旧的 `#docs/guide.md` 形式也仍然可用。

**想改代码**：`js/app.js` 顶部是设置默认值，`PRESETS` 是内置背景；`styles/tuning.css` 是所有尺码与按钮玻璃配方；`styles/controls.css` 最后一节是按钮的统一材质；`styles/markdown.css` 是正文排版（与 dsh 一致的部分，改它前先看 `tools/check-styles.mjs`）；改完 `sample.md` 要跑一次 `node tools/build-sample.mjs`，改完前端要跑一次 `node tools/build-share.mjs`（否则单文件版与 `share/` 还是旧的）。
